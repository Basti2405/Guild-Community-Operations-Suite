Warum es das gibt

Why this exists

Gildenführung besteht zu einem guten Teil aus Nachfragen: Wer hat seine Verzauberungen? Wer war letzte Woche dabei? Wer hat seine Schatzkammer noch offen? Die Antworten stehen im Spiel — nur verteilt über Fenster, die sich nicht nebeneinanderlegen lassen.

Running a guild means asking the same questions over and over: who has their enchants? Who showed up last week? Whose vault is still unclaimed? The answers are in the game — just spread across windows you cannot put side by side.

GuildOps liest sie einmal aus und gibt sie als JSON weiter — an eine Tabelle, ein Web-Dashboard, was auch immer draußen darauf wartet. Der Weg nach draußen ist hier kein Nachgedanke, sondern der Zweck.

GuildOps reads them once and hands them on as JSON — to a spreadsheet, a web dashboard, whatever is waiting outside. Getting the data out is not an afterthought here, it is the point.

Warum schon jetzt öffentlich

Why public already

Ein Addon, das Daten über die eigene Gilde nach außen gibt, sollte nachlesbar sein. Wer es einsetzt, soll im Quelltext sehen können, was genau den Rechner verlässt — und was nicht.

An addon that hands guild data to the outside world should be readable. Anyone using it should be able to see in the source what exactly leaves their machine — and what does not.

Es ist ausdrücklich noch kein fertiges Addon. Was steht und was fehlt, sagt die Übersicht weiter unten — und die Planungsunterlagen im Repository sagen es genauer.

This is explicitly not a finished addon yet. What works and what is missing is listed below — and the planning documents in the repository say it in more detail.

Aufbau

Structure

Mehrere eigenständige Addons in einem Repository. Jedes Modul trägt ## Dependencies: GuildOps und lässt sich einzeln abwählen – wer es nicht braucht, hat seinen Quelltext nicht im Speicher.

Several standalone add-ons in one repository. Each module declares ## Dependencies: GuildOps and can be disabled individually – what you do not need is not loaded.

GuildOps/                Kern  – Audit, Speicher, JSON-Ausfuhr
GuildOps_Attendance/     Modul – Anwesenheit
GuildOps_LootAudit/      Modul – Item-Verteilung
GuildOps_ChannelSync/    Modul – Abgleich zwischen Installationen

Der Kern kennt kein Modul namentlich. Er ruft nur Haken auf; wer sich angemeldet hat, wird gefragt. Ein Modul, das seine Voraussetzung nicht findet oder in einem Haken wirft, wird stillgelegt – nicht der Kern.

The core knows no module by name. It only calls hooks. A module that fails its check, or throws inside a hook, is disabled – the core is not.

Was es tut

What it does

Ausfuhr als JSON

JSON export

/gops export öffnet ein Textfeld zum Kopieren. Nicht die SavedVariables — das ist Lua-Quelltext, den ein Server ausführen müsste. Schlüssel sind sortiert, damit sich zwei Stände vergleichen lassen.

/gops export opens a text box to copy from. Not the SavedVariables — that is Lua source a server would have to execute. Keys are sorted so two snapshots can be compared.

Eigener Stand statt Fremd-Inspektion

Own state, not inspection

Inspect geht nur in Reichweite und schlägt oft fehl. Deshalb erhebt jeder Spieler seinen eigenen Stand — die einzige Angabe, die verlässlich ist.

Inspect only works in range and often fails. So every player records their own state — the only reliable source.

Roster, das den Unterschied kennt

A roster that knows the difference

Ein noch nicht geliefertes Guild Roster gibt nil zurück, nicht eine leere Liste. Sonst meldet das Addon „0 Mitglieder“ und schickt den Offizier auf die falsche Fährte.

A roster that has not arrived yet returns nil, not an empty list. Otherwise the add-on reports “0 members” and sends the officer looking in the wrong place.

Was es nicht kann

What it cannot do

Ehrlichkeit an dieser Stelle ist wichtiger als eine vollständig aussehende Funktionsliste.

Being honest here matters more than a feature list that looks complete.

  • Es untersucht keine fremden Charaktere. Ohne das Sync-Modul sieht ein Offizier nur seine eigenen Charaktere — nicht die halbe Gilde.
  • It does not inspect other characters. Without the sync module an officer sees only their own characters — not half the guild.
  • Der Great Vault anderer ist nicht abfragbar. Diese Angabe kann nur von dem kommen, der sie selbst beisteuert.
  • Other players’ vaults are not queryable. That information can only come from the person contributing it.
  • Es weiß nicht, wer eingeplant war. Das Spiel kennt keinen Kader. Wer gefehlt hat, ergibt sich erst im Abgleich mit einer Liste von außen.
  • It does not know who was rostered. The game has no concept of a roster plan. Who was missing only emerges from comparing against an external list.
  • Gems prüft es noch nicht. Der Itemlink verrät nicht, wie viele Gem-Plätze ein Stück hat; ein leeres Feld heißt nicht zwingend „Gems fehlt“. Lieber keine Prüfung als eine, die Lücken meldet, die keine sind.
  • It does not check gems yet. The item link does not reveal how many sockets an item has; an empty field does not necessarily mean “gem missing”. Better no check than one reporting gaps that are not there.
  • Es schickt nichts von selbst ins Netz. Das ist eine Grenze von WoW, kein fehlendes Feature.
  • It never sends anything on its own. That is a WoW limitation, not a missing feature.

Entwickeln

Development

tools/junction.cmd    # verbindet alle Addon-Ordner mit dem AddOns-Verzeichnis
./tools/test.sh       # Syntax, .toc-Abgleich und Logiktests (baut sich Lua 5.1)

Die Tests laufen ohne WoW: Die Spielumgebung wird so weit nachgebaut, wie der Kern sie anfasst. Der JSON-Schreiber ist eigener Code mit echten Fallstricken — Maskierung, Liste gegen Objekt, nan und inf, stabile Reihenfolge. Genau deshalb ist er getestet.

Tests run without WoW: the game environment is stubbed out as far as the core touches it. The JSON writer is hand-written code with real pitfalls — escaping, array vs object, nan and inf, stable ordering. Which is exactly why it is tested.
